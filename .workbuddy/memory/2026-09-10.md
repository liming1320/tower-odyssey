## 2. 服务端（server.js）
- **存储方案**：ROM 二进制存 `data/roms/<id>.bin` 磁盘文件（gitignore 已加），元数据 `DB.roms[]` 走 save()（db.json / MySQL 模式均兼容）——二进制大文件不塞 JSON/MySQL，磁盘+元数据是通行做法
- **路由**：
  - `GET /api/roms`（登录）→ `{roms:[元数据], admin:bool}`（admin 字段告知前端是否显示导入区）
  - `GET /api/roms/download?id=`（登录）→ 流式回传文件
  - `POST /api/roms/upload?name=&core=`（管理员）→ 原始二进制流式落盘，512MB 上限，带背压
  - `POST /api/roms/delete`（管理员）→ 元数据+磁盘文件一起清
- **管理员判定**：`romAdminOk` 双通道——后台独立令牌（admin/workbuddy 的 `__admin__`）或玩家端 isAdmin 账号（第一个注册的玩家）
- **关键坑**：路由分发对所有 POST 先 `readBody`（JSON 字符串解析毁二进制）→ 上传路径在分发处特判跳过；上传 handler 首版漏了 `out.write(c)`（只计数没写盘，下载 0 字节），修复+背压

## 17. 模拟器 iframe 高度 CSS bug → 找不到键位设置的根因

**用户反馈**：「控制设置只有重置，清除，关闭，没有设置键位的地方啊」（带截图）

**我先入为主判断错了**：以为是文案指错入口，先去改介绍区。经 web 检索 + 真实浏览器探针才看清真相。

**根因**：CSS `.emu-frame { flex: 1; width: 100%; }` **缺 `min-height: 0`**，iframe 有 300×150 的内置默认尺寸，flex:1 撑不开它，**iframe 实际只有 150 像素高**。mini-stage 是 836 高，但 iframe 只占顶部 150 像素。所以玩家看到的「控制设置」面板只有标题 + 玩家 1-4 tabs + 重置/清除/关闭；下面其实有完整的按键映射表（玩家 1/2/3/4 tabs → 游戏手柄/键盘 子切换 → 16 行 A/B/选择/开始/向上/向下/向左/向右/SWAP DISKS/EJECT/INSERT DISK/快速保存状态/快速加载状态/改变状态槽/快进/慢动作/快退 + 每行右侧【设置】按钮 `<a class="ejs_control_set_button">`），全部都在可视区外。

**探针路径**（用 CDP 真实浏览器探测）：
1. probe-emu-desktop.js 拿 iframe docElement.clientHeight = 150（应为 836）
2. 探测外层 .mini-mask/stage/play 链：全部 836/880，唯有 .emu-frame = 150
3. probe-setbtn.js 发现「设置」按钮实际是 `<a class="ejs_control_set_button">`，不是 `<button>`
4. 修 CSS：`flex: 1 1 0; height: 100%; min-height: 0` 后 iframe 升到 836
5. 控制设置 modal 全可见，16 行映射 + 16 个【设置】按钮全部显示

**改键真实方法**：
- 打开游戏 → 顶部「≡ 菜单」 → 「控制设置」
- modal 内：选玩家 1-4 → 切「键盘」标签 → 找到动作行（A/B/选择/开始/向上/...）→ 点最右【设置】→ 按下新键（键盘/手柄均可）→ 自动保存

**默认键位（FC/NES，已修正之前的错误）**：方向键=十字键 · **Z=A · X=B · V=选择 · Enter=开始** · Q=L · E=R · 1/2/3=快速存档/读档/换槽

**代码改动**：
- `public/css/main.css` `.emu-frame` 加 `flex: 1 1 0; height: 100%; min-height: 0`
- `public/js/minigames/emulator.js` 介绍区全部重写为正确的默认键位和导航路径
- `tools/smoke-emulator.js` 加 iframe 高度断言 + 控制设置 modal 可见行数 + 设置按钮数（用 `a.ejs_control_set_button`）
- 探针脚本（probe-*）和临时截图删除

**验证**：冒烟 26/26 全过 · 全量审计 107 款 0 异常

**教训**：用户报告「没有这个功能」时，先用真实浏览器探针验证「是 DOM 真没有还是被遮挡」再下结论。CSS 容器+flex 子项的内置尺寸（iframe 默认 300x150、textarea 默认 25×2 等）经常吃掉 flex:1，需要 `min-width/min-height: 0` 显式放行。
